# 常见错误模式速查

这些模式只提供调查方向，不能替代项目证据。

| 类型 | 常见信号 | 根因方向 | 最小验证 | 预防方向 |
|---|---|---|---|---|
| 语法/类型 | 解析失败、未定义名称、签名不匹配 | 改动未同步、作用域或类型假设错误 | linter、类型检查、最小复现 | 在改动入口和调用方后运行静态检查 |
| 配置/依赖 | 缺包、未知配置键、版本冲突 | 环境未同步、作用域错误、文档过期 | 查看锁文件、实际配置、官方文档 | 锁版本、配置解析测试、示例配置 |
| 逻辑/状态 | 空值、死循环、竞态、状态卡死 | 边界遗漏、清理路径缺失、并发假设 | 针对边界写复现测试 | finally/清理、超时、状态不变量 |
| 环境/权限 | 路径不存在、编码、拒绝访问、端口占用 | 跨平台假设、沙箱边界、遗留进程 | 解析绝对路径、检查权限与进程 | 运行前探测、明确授权、可移植路径 |
| 第三方 | API 变更、服务错误、限流 | 版本/协议变化、外部状态 | 查当前官方文档和响应 | 固定兼容范围、重试/降级、契约测试 |
| 流程/验证 | “测试通过”但产物旧、改错文件、遗漏引用 | 验证对象不对、范围检查缺失 | 校验产物时间/哈希、Git diff | 明确完成条件和变更边界检查 |

## 使用规则

1. 先记录原始证据，再匹配模式。
2. 模式匹配只能提高调查优先级，不能直接证明根因。
3. 修复后使用能够反驳原故障的命令验证，而不是只确认命令退出码为 0。
4. 涉及更新中的库、服务或 Codex 配置时，优先查当前官方文档。
