# Codex 技能漏洞审计指南

审计 `~/.agents/skills/<name>/SKILL.md` 或项目 `.agents/skills/<name>/SKILL.md`，重点找导致本次错误可重复发生的程序性缺口。

## 三类漏洞

### 1. 前置条件或禁止条件缺失

技能给出动作，但没有说明何时不能执行、需要何种权限或作用域。

检查：

- 是否要求先读适用的 `AGENTS.md`；
- 是否验证目标路径、权限、配置项或依赖；
- 是否区分只读、写入和破坏性操作；
- 是否保护并行工作的未提交改动。

### 2. 边界与失败路径遗漏

技能覆盖主流程，却没有处理空输入、不可访问历史、特殊字符、大文件、超时、目标已存在或外部服务失败。

检查：

- 失败后是否停止、降级或回滚；
- 是否把推测误写成事实；
- 是否假定固定目录、日志格式或平台行为；
- 是否给出安全的替代数据源。

### 3. 验证与完成条件缺失

技能只说“检查/确保正确”，没有规定验证对象和命令。

检查：

- 是否读回修改文件；
- 是否运行最小测试、解析器、类型检查或构建；
- 是否检查 `git diff` 和路径边界；
- 是否验证真正产物，而非仅验证中间命令。

## 建议修改原则

- 修复原规则位置，不在文件尾追加“补丁区”。
- 规则应包含触发条件、动作、禁止项和验证方法。
- 保持技能简洁；只加入可复用且低副作用的规则。
- 修改 skill 前必须获得用户确认，并避免覆盖其他人的并行改动。

## 输出格式

```markdown
### 技能漏洞：$skill-name
- 类型：前置条件缺失 / 边界遗漏 / 验证缺失
- 文件：<绝对路径>
- 位置：<标题或行号>
- 触发错误：<ERROR_LOG 条目或证据>
- 建议：<具体改法>
- 验证：<修改后检查>
```
