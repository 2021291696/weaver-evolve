# 记忆合并示例

## 重复规则：保留一个权威版本

现状：

- `~/.codex/AGENTS.md`：所有 Python 项目使用 uv。
- 项目 `AGENTS.md`：Python 依赖不要用 pip，使用 uv。
- 项目 `docs/dev.md`：本项目通过 uv 管理。

处理：

1. 若用户确实要求所有项目统一使用 uv，保留全局硬规则。
2. 项目 `AGENTS.md` 删除语义完全重复的规则；若项目有额外命令，仅保留项目差异。
3. `docs/dev.md` 可保留操作说明，因为它服务于人类文档，不与规则文件职责相同。

不要为了“去重”删除不同受众所需的信息。

## 新决定推翻旧决定

现状：项目知识写“数据库用 SQLite”，用户后来明确改为 PostgreSQL。

处理：

1. 搜索 SQLite 的规则、配置、设计说明和索引。
2. 将权威决策更新为 PostgreSQL，并注明生效条件；不保留两个并列的当前决策。
3. 历史设计文档若需要保留，明确标记“已废弃/历史方案”，不要伪装成当前规则。
4. 检查 `.codex/config.toml` 或项目配置是否真的涉及该决定；不相关则不改。

## 规则层级下沉

现状：全局 `~/.codex/AGENTS.md` 写着“前端包必须运行视觉回归”，但只对某个 monorepo 的 `apps/web` 生效。

处理：

1. 从全局规则移除。
2. 写入 `<项目>/apps/web/AGENTS.md`，前提是用户确认且该目录确为适用边界。
3. 检查父级 `AGENTS.md` 是否有冲突或重复。

## 知识关联而非合并

现状：两个独立笔记分别记录 Windows 编码问题和某打包工具的中文路径问题，它们共享部分根因。

处理：保留两个主题文件，在各自合适位置增加交叉链接；不要把不同工具的完整排障过程硬合成一篇。

## 忘掉信息后的清理

用户要求忘掉一个旧端口：

1. 删除当前知识文件中的端口值。
2. 更新引用该值的索引或摘要。
3. 搜索同义表达和配置说明。
4. 不声称已从 Git 历史、备份或不可访问的 Codex 历史中抹除。

## 不应执行的“整理”

整理现有记忆时看到对话里有一条新偏好，但它从未写入任何目标文件。

不要顺手新增。先把它列为 `$weaver-自我迭代` 或新的“记住”请求候选，避免把结构整理和信息提取混在一起。
